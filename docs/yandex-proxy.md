# Прокси для Яндекс Музыки на сервере в РФ

tbot остаётся в Европе и обращается к Telegram и другим провайдерам как раньше.
Только клиент Яндекс Музыки использует российский HTTP-прокси:

```text
tbot (Европа) → Squid (РФ, TCP 3128) → api.music.yandex.net:443
```

Ниже пример для отдельного сервера с Ubuntu 24.04 и Squid 6. Конфигурация также
использует директивы Squid 5/7; для Squid 8 её нужно пересмотреть.
Команды рассчитаны на fish. Здесь приведены инструкции, они не выполняются
автоматически при запуске tbot.

## 1. Проверить доступность API из РФ

На российском сервере:

```fish
curl --noproxy '*' --connect-timeout 5 --max-time 15 --include 'https://api.music.yandex.net/tracks/58314507'
curl --noproxy '*' --connect-timeout 5 --max-time 15 --include 'https://api.music.yandex.net/search?type=track&text=Champs'
```

Проверьте HTTP-статус и содержимое JSON: получение трека должно возвращать
название и исполнителя, поиск — список треков. Наличие российского IP само по себе
не гарантирует доступ: ошибки авторизации, ограничения конкретного адреса или
изменения API нужно устранить до подключения прокси.

## 2. Установить и настроить Squid

Для примера используются адреса из документационных диапазонов. Замените:

| Значение | Что указать |
| --- | --- |
| `198.51.100.20` | Доступный из Европы IP российского сервера |
| `203.0.113.10/32` | Реальный исходящий IPv4 европейского сервера, видимый серверу РФ |

Если бот работает в Docker, обычно это IP хоста после NAT. При другой схеме сети
проверьте адрес по сетевой конфигурации и журналу Squid.

На сервере в РФ:

```fish
sudo apt-get update
sudo apt-get install -y squid
squid -v
sudo cp -n /etc/squid/squid.conf /etc/squid/squid.conf.before-tbot
sudoedit /etc/squid/squid.conf
```

Для выделенного экземпляра Squid замените содержимое файла конфигурацией из
[`squid-yandex.conf.example`](squid-yandex.conf.example), предварительно исправив
`203.0.113.10/32`. Не дописывайте её после стандартных `http_access allow`:
правила проверяются по порядку. Если Squid уже обслуживает другие приложения,
используйте отдельный экземпляр, чтобы не заменить их правила.

Конфигурация разрешает только CONNECT с европейского сервера к
`api.music.yandex.net:443`. Остальные источники, домены, порты и обычные HTTP-запросы
запрещены. DNS имени API разрешает российский сервер. TLS остаётся между tbot
и Яндексом: перехват HTTPS и установка своего корневого сертификата не нужны.

В firewall сервера и панели хостинга разрешите входящий TCP 3128 только с
исходящего IP европейского сервера; остальные источники должны быть запрещены.
При уже включённом UFW с политикой запрета входящих соединений:

```fish
sudo ufw status verbose
sudo ufw allow from 203.0.113.10 to any port 3128 proto tcp
```

Проверьте, что нет более широкого разрешения на 3128. Если UFW выключен,
настройте действующий firewall или правила хостинга; не включайте его без проверки
доступа по SSH.

Проверьте конфигурацию, затем запустите сервис:

```fish
sudo squid -k parse
sudo systemctl enable squid
sudo systemctl restart squid
sudo systemctl status squid --no-pager
sudo ss -ltnp 'sport = :3128'
```

Перезапускайте Squid только после успешного `squid -k parse`.

Если между серверами уже настроен WireGuard, можно использовать его адреса:
в `http_port` укажите приватный IP сервера РФ вместо `0.0.0.0`, в `tbot_server` —
приватный IP европейского сервера `/32`. Разрешите порт только внутри туннеля,
не открывая его в Интернет. Общий маршрут трафика бота менять не требуется.

## 3. Проверить прокси из Европы

На европейском сервере:

```fish
curl --noproxy '' --proxy http://198.51.100.20:3128 --connect-timeout 5 --max-time 15 --include 'https://api.music.yandex.net/tracks/58314507'
curl --noproxy '' --proxy http://198.51.100.20:3128 --connect-timeout 5 --max-time 15 --include 'https://api.music.yandex.net/search?type=track&text=Champs'
```

Ожидается успешный CONNECT, затем HTTP 200 с данными API. Сравните результаты
с прямыми запросами из РФ. Запрос к постороннему домену должен быть отклонён:

```fish
curl --noproxy '' --proxy http://198.51.100.20:3128 --connect-timeout 5 --max-time 15 --include https://example.com
```

Ожидается отказ CONNECT с кодом 403. С другого исходящего IP доступ также должен
блокироваться firewall либо Squid. На сервере РФ смотрите журнал:

```fish
sudo tail -n 50 /var/log/squid/access.log
sudo journalctl -u squid -n 50 --no-pager
```

Для разрешённых туннелей в access.log ожидается `TCP_TUNNEL/200` и
`api.music.yandex.net:443`. Запись о туннеле может появиться только после его закрытия.
Это подтверждает соединение, а корректность ответа API проверяется отдельно.

## 4. Подключить tbot

Из корня репозитория на европейском сервере:

```fish
env TBOT_YANDEX_PROXY_URL=http://198.51.100.20:3128 docker compose up -d --build app
```

Для постоянной настройки добавьте `TBOT_YANDEX_PROXY_URL=http://198.51.100.20:3128`
в `.env`, который использует Docker Compose. Если свой deployment задаёт environment
контейнера отдельно, добавьте переменную в него. Адрес `127.0.0.1` внутри контейнера
указывает на сам контейнер, поэтому используйте доступный адрес сервера РФ.

При запуске бинарника без Docker доступны два варианта:

```fish
env TBOT_YANDEX_PROXY_URL=http://198.51.100.20:3128 ./tbot
./tbot --yandex.proxy_url=http://198.51.100.20:3128
```

Флаг имеет приоритет над переменной окружения. Поддерживаются `http://` и `https://`,
необязательные учётные данные в URL и адреса IPv6 в квадратных скобках.
В примере Squid авторизация основана на IP, логин и пароль не требуются.
У обычного HTTP-прокси CONNECT-заголовки не зашифрованы; при использовании пароля
выберите защищённый канал или HTTPS-прокси с доверенным сертификатом.

Прокси применяется к определению трека и поиску в Яндекс Музыке. Он имеет приоритет
над `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` для этого клиента. Пустое значение
сохраняет стандартное поведение Go с этими переменными окружения. Другие провайдеры
не получают новую настройку. Полный URL прокси не выводится в стартовую конфигурацию.
Таймаут запроса — 10 секунд. Если прокси недоступен, запрос завершается ошибкой;
автоматического перехода на прямой запрос нет.

Проверьте в Telegram оба сценария: ссылка Яндекса → название и ссылки остальных
сервисов; ссылка другого сервиса → ссылка Яндекса. Убедитесь, что сообщения
Telegram и остальные провайдеры продолжают работать.

## Диагностика и откат

| Симптом | Что проверить |
| --- | --- |
| Ошибка `invalid yandex.proxy_url` при запуске | Схема, хост, числовой порт 1–65535; путь, query и fragment не допускаются, кроме завершающего `/` |
| Timeout / connection refused | Доступность TCP 3128 из контейнера, firewall, адрес и состояние Squid |
| Отказ CONNECT 403 | Исходящий IP после NAT и порядок ACL; домен назначения должен быть `api.music.yandex.net` |
| CONNECT успешен, но API вернул ошибку | Сравнить прямой запрос из РФ; проверить тело ответа и ограничения API |
| Ошибка сертификата | Часы, доверенные CA и имя HTTPS-прокси; проверку TLS не отключать |

Для отключения отдельного прокси уберите постоянное значение из `.env` или
deployment и пересоздайте контейнер:

```fish
env TBOT_YANDEX_PROXY_URL= docker compose up -d app
```

Это возвращает стандартный выбор прокси Go, но не устраняет исходное ограничение
доступа из Европы. Если выделенный Squid больше не используется, на сервере РФ
его можно остановить и убрать соответствующее разрешение firewall:

```fish
sudo systemctl disable --now squid
sudo ufw delete allow from 203.0.113.10 to any port 3128 proto tcp
```

Команда UFW применима, если правило было добавлено через UFW; правила хостинга
удаляются в его панели.
