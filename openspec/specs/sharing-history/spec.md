# sharing-history Specification

## Purpose
Сохранять отправки ссылок отдельно от кеша и переносить историю между установками с точными авторами и датами там, где они известны.

## Requirements

### Requirement: Record sharing events independently
Система SHALL сохранять отправителя, чат, сообщение, дату, провайдера и URL каждой обрабатываемой музыкальной ссылки, включая попадания в кеш.

#### Scenario: A second user shares a known track
- **WHEN** другой пользователь присылает уже известную ссылку
- **THEN** его отправка сохраняется отдельно, а первый отправитель кеша не заменяется поздней отправкой

### Requirement: Extract Telegram HTML
Утилита SHALL извлекать ссылки из Telegram HTML, сохраняя авторов и даты, поддерживать последовательные страницы и наследование автора в объединённых сообщениях.

#### Scenario: Joined message and preview
- **WHEN** сообщение без повторного заголовка автора содержит ссылку, также представленную в основном превью
- **THEN** сохраняется одна отправка этого URL от автора предыдущего объединённого сообщения

#### Scenario: Explicit timezone and excluded accounts
- **WHEN** оператор задаёт часовой пояс и ID исключаемого бота
- **THEN** локальные даты интерпретируются в указанном поясе, а ответы исключённого аккаунта не становятся рекомендациями человека

#### Scenario: Desktop numeric timestamp includes an offset
- **WHEN** HTML содержит дату вида `02.07.2019 12:25:35 UTC+03:00`
- **THEN** отправка сохраняется с UTC-временем `2019-07-02T09:25:35Z` независимо от заданного часового пояса; некорректные даты отражаются в отчёте

### Requirement: Honest missing metadata
Утилита SHALL сохранять доступное имя неизвестного или удалённого аккаунта с `user_id=0`, не угадывать ID по имени и сообщать о неполных или некорректных данных.

#### Scenario: Deleted account
- **WHEN** HTML содержит имя `Deleted Account`, но не содержит числового ID
- **THEN** ссылки сохраняются с исходным именем и неизвестным ID без привязки к другому участнику

### Requirement: Preview and atomic import
Импорт SHALL сначала поддерживать проверку без открытия базы, требовать `--apply` для записи и применять данные транзакционно без дублей при повторном импорте того же архива.

#### Scenario: Preview only
- **WHEN** команда импорта выполнена без `--apply`
- **THEN** выводится предварительный результат, а SQLite не открывается и не создаётся

#### Scenario: Repeat or failed import
- **WHEN** тот же архив импортируется повторно либо во время записи возникает ошибка
- **THEN** повторный импорт не добавляет дубли его отправок, а ошибка записи откатывает транзакцию данных

### Requirement: Portable read-only export
Экспорт SHALL читать существующую базу без изменения схемы, сохранять отправки, кеш и исторические алиасы в версионированный JSON и не перезаписывать существующие выходные файлы.

#### Scenario: Round trip
- **WHEN** валидный архив, укладывающийся в ограничения импорта, экспортирован и импортирован в другую установку
- **THEN** сведения об отправках, кеш и сохранённые алиасы остаются доступны

#### Scenario: Two users shared one normalized URL
- **WHEN** импортированная история содержит отправки одного трека двумя пользователями с разными трекинговыми параметрами
- **THEN** после перезапуска и export/import оба пользователя видят трек в своём списке, а кеш остаётся общим

### Requirement: Offline import and incomplete historical cache
Утилиты истории SHALL работать без запуска Telegram и музыкальных API; неподтверждённые исторические треки SHALL допроверяться при следующем использовании.

#### Scenario: Import an HTML-derived archive
- **WHEN** оператор применяет подготовленный архив
- **THEN** сообщения в чат не рассылаются, исходные даты сохраняются, а актуальные соответствия сервисов не выдумываются из старых превью

### Requirement: Bounded versioned archives
Чтение архива SHALL принимать версию 1, не более 100 MiB JSON и суммарно не более 200 000 записей `shares`, `cache` и `aliases`; неподдерживаемая версия или превышение лимитов SHALL завершать импорт ошибкой до записи данных.

#### Scenario: Unsupported or oversized input
- **WHEN** версия не равна 1, размер превышает 100 MiB либо суммарное число записей превышает 200 000
- **THEN** импорт отклоняется без частичного применения архива

### Requirement: Bind only unassigned chat history
Параметр `--chat-id` SHALL назначать чат только отправкам с `chat_id=0`, не переносить события из уже известного чата и не разрешать запись оставшихся непривязанных отправок.

#### Scenario: Archive includes known and unknown chats
- **WHEN** архив содержит отправки с известным чатом и с `chat_id=0`, а оператор задаёт ненулевой `--chat-id`
- **THEN** известные чаты сохраняются, а заданный ID получают только непривязанные отправки

#### Scenario: Unbound shares remain
- **WHEN** после привязки в архиве остались отправки с `chat_id=0`
- **THEN** применение отклоняется до записи истории
